## 多步骤流程：先列 todo 清单，再逐步核对

当用例包含多个有先后依赖的步骤（例如：登录 → 进入列表 → 打开详情 → 提交），
页面信息必须在**每一步交互之后**才能获得——后续步骤的页面此刻还不存在。
此时不要试图一次性核对完所有步骤，而要按下面的方式推进：

1. **先列清单**：调用 `todo_write` 列出待核对清单，每项写明「该步骤要做什么交互」
   与「该步骤需要确认哪些关键元素」。这一步是必须的——用户在界面上据此看到你的计划；
2. **逐项推进**：一次只推进一项。先把当前项置为 `in_progress`，
   完成该步骤的交互后核对该步骤的关键 DOM 信息，再把它置为 `completed`；
3. **边做边记**：每完成一项就更新清单（每次都提交**完整清单**），
   并记录该步骤核对到的定位方式——这些记录就是后续写脚本的直接依据。

例如（`todo_write` 的 items 示意，实际以结构化参数提交）：

```text
- [~] 步骤1 登录：填写用户名/密码 → 点击登录 → 确认跳转到首页
- [ ] 步骤2 打开模板列表：点击「模板管理」→ 确认列表表格出现
- [x] 步骤3 打开预览弹框：点击行内「实际预览」→ 确认弹框容器与画布元素
```

### 第一步是登录时：先过登录，再列后续清单

登录是典型的多步骤门槛：**不过这一关，后面每一步的页面都不存在**，
凭推断写出的 selector 全是猜测。因此：

1. 把「登录」本身作为清单的**第一项**，先集中把它做完：
   用 `browser_fill` 填账号密码（密码写 `${ENV:KEY}` 引用，见「页面核对」一节），
   再 `browser_click` 提交，用 `browser_waitFor` 等待跳转；
2. 登录成功后**更新清单**，再继续列后续步骤——
   后续步骤的待核对元素此时才可能被看到，之前列的清单若含猜测，现在要按实际情况修正；
3. 若登录卡住（验证码、二次验证、账号不可用），**只把登录这一项标为断点**，
   在说明中写清卡在哪一步、页面要求什么，不要在清单里伪造「已完成」。
